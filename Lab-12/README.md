# Lab 12 - 1A2B猜數字遊戲（UART通訊版）

## 實驗概述
本實驗實作一個雙人對戰的1A2B猜數字遊戲，使用UART進行兩塊開發板之間的資料通訊。遊戲支援即時對戰，玩家可以同時猜測對方的密碼，並透過LCD顯示猜測歷史記錄。

## 硬體環境
- **開發板**: Nu-LB-NUC140（需要兩塊開發板）
- **微控制器**: NUC140VE3CN
- **LCD顯示器**: 顯示猜測歷史記錄
- **七段顯示器**: 顯示自己的密碼（僅供參考）
- **按鍵矩陣**: 輸入猜測數字
- **UART通訊**: 兩塊開發板之間的資料傳輸

## 硬體連接說明

```
功能模組        →    GPIO腳位/介面    說明
UART1_TX        →    PB5             資料發送
UART1_RX        →    PB4             資料接收
LCD顯示器       →    SPI3            顯示猜測歷史
七段顯示器      →    PC4-7, PE0-7    顯示自己的密碼
按鍵矩陣        →    PA0-5           輸入猜測數字
Timer0          →    系統時鐘        按鍵掃描（50Hz）
Timer1          →    系統時鐘        七段顯示器多工（200Hz）
```

## 遊戲規則

### 1A2B規則說明
- **A (位置正確)**: 數字正確且位置正確
- **B (數字正確)**: 數字正確但位置錯誤
- **範例**: 密碼為 `1234`，猜測為 `1356`
  - `1` 在正確位置 → 1A
  - `3` 數字正確但位置錯誤 → 1B
  - 結果: **1A1B**

### 遊戲流程
1. **系統初始化**: 自動產生4位不重複數字的密碼
2. **輸入猜測**: 使用按鍵輸入4位數字
3. **發送猜測**: 自動發送給對手
4. **接收猜測**: 接收對手的猜測
5. **計算結果**: 計算1A2B結果
6. **顯示歷史**: 在LCD上顯示最近4筆猜測記錄

## 技術重點

### UART通訊協定
- **傳輸速率**: 115200 baud
- **資料格式**: 8位資料，無同位檢查
- **通訊方式**: 半雙工，輪詢式發送
- **資料格式**: 4個連續位元組（4位數字）

### 中斷處理機制

#### Timer0中斷（按鍵掃描）
- **頻率**: 50Hz（每20ms掃描一次）
- **功能**: 檢測按鍵按下事件
- **防彈跳**: 使用邊緣檢測（按下瞬間觸發）

#### Timer1中斷（七段顯示器）
- **頻率**: 200Hz（每5ms切換一位）
- **功能**: 多工掃描4位七段顯示器
- **顯示內容**: 自己的密碼（供參考）

#### UART1中斷（資料接收）
- **觸發條件**: 接收資料就緒（RDA）
- **功能**: 接收對手的猜測數字
- **緩衝區**: 4位元組緩衝區

### 1A2B演算法
```c
Calculate_1A2B(secret, guess, &A, &B)
1. 計算A（位置正確）:
   - 遍歷每個位置
   - 如果 secret[i] == guess[i]，A++

2. 計算B（數字正確但位置錯誤）:
   - 對於每個 guess[i]（位置不正確）
   - 在secret中尋找相同數字
   - 如果找到，B++
```

### 密碼產生演算法
```c
Generate_Secret()
1. 使用rand()產生隨機數
2. 檢查重複性
3. 確保4位數字都不重複
```

## 注意事項
- **硬體連接**: 兩塊開發板的UART需要交叉連接（TX→RX, RX→TX）
- **通訊速率**: 確保兩塊開發板使用相同的baud rate
- **時序控制**: 按鍵掃描頻率影響輸入響應速度
- **資料同步**: 確保資料完整接收（4位元組）
- **防彈跳**: 按鍵輸入需要適當的防彈跳處理
- **記憶體管理**: 注意緩衝區大小和溢出保護
